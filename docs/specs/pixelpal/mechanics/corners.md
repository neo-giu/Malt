# Corner rules A-C mechanics (T01b)

Differences from plan Task 1b as written:
- `line_violations` signature is `(mask, exempt=None, surface=None, kinds=None, rules=(), background=None)`: `surface`
  (T01) stays third so old callers keep working. `line_check.py` also gets `marker_kinds`, `overlap_mask`; `marker_mask`
  includes orange. CLI `--rules` prints "kept by <rule>" counts (rule off minus rule on) and per 100 line px.
- Rule A ring count uses out-of-frame = no line. A block inside a 3x3 all-line square is never allowed (same test in
  the shader: `_junction_block`).
- Rules B and C must also guard the Zhang-Suen pass (`PIXEL_LINES_ZS`), not only THIN: ZS removes any pixel with
  b = 2, a = 1, so it would delete a corner THIN kept. `_kept_corner(p, value)` is shared by THIN and ZS; it is false
  for any pixel that is not an L corner. `line_data` is bound to THIN, ZS and BLOCK (plan names THIN and BLOCK only).
- Kinds for rule C in the shader: ring (silhouette, KEEP), overlap (a > 0.95), inner. In line_check 'k' counts as 's'.
- FaceSDF.glsl: `line_data = vec4(1.0, float(1 | (...)), 0.0, 1.0)` in ONE statement crashes Blender at file load
  (access violation in `idp_from_PySequence`, before any script runs; reproduced 3x in `blender -b`, gone when the
  expression sits in its own `float rule_bits = ...;` statement, as in PixelCel.glsl). Use two statements.
- `blender -b` always ends with an access violation at exit (OpenGL teardown); it is noise once the script printed.
